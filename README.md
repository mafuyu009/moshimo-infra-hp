## 投稿が増えたら（台帳ワークフロー）

`index.html` 内の `<script>` 冒頭の `PREFS` が台帳。1本投稿したら:

1. 該当県の `status` を `"posted"` に変える（新規は1件追加）
2. `food / foodValue / water / siege / special / source / reel` を埋める
3. GitHub リポジトリへ push する → Altare が自動でデプロイし、公開ページに反映される

これだけ。重くしない。投稿フロー側（Instagram投稿ジョブ等）で 1〜2 を行い、push までを同じ流れに組み込む想定。

## Altare へ上げる手順（公開時、2026-11-22夜に方式変更）

前提：Altare App Hosting は GitHub リポジトリから動く。ドラッグ&ドロップ型ではないので、間に GitHub を1つ挟む。

初回だけ（本人の作業）:
1. Altare に Always Free でアカウント登録（クレジットカード不要、費用なし）
2. GitHub アカウントを用意し、このフォルダを置くリポジトリを作成（Muse側でファイル構成は準備可能。リポジトリ作成と連携許可は本人のアカウント操作）
3. Altare コンソールで Apps → New app → GitHub repository を選び、Altare GitHub App の連携を許可。Runtime は Static site、Root はリポジトリ直下（または hp-prototype フォルダ）を指定

初回だけ（Museの作業）:
4. 雛形をリポジトリへ push する。初回デプロイが走り、`名前.go.altare.global` の HTTPS アドレスが発行される
5. 発行URLで表示・データカード・リールリンクを確認する

2回目以降（毎回の投稿時）:
- PREFS を書き換えて push するだけ。Altare は push ごとに自動デプロイする。`altr deploy` を使う場合も「GitHub上の最新コミット」が対象なので、必ず push が先

独自ドメインは後から（CNAME＋証明書自動、1アプリ5つまで）。取得費用は年1,000〜2,000円程度で、事前共有必須のルール通り未取得。

無料枠の注意: Altare Always Free はチーム全体でメモリ6GB・ディスク10GB共有。静的HPなら消費はごく小さい見込み。スリープなし24時間稼働、静的ファイルはエッジキャッシュあり。
Netlify 案は予備として残す（帯域クレジット制が弱点だったため本線から外した）。
